Use Doriterm from an MCP client

An assistant that speaks the Model Context Protocol (MCP) can use your machine's terminals through Doriterm: list them, read a screen, send a message to an agent, run a command.

What you can do with this

Through MCP, a cloud agent such as a Grok bot or Dots works in the environment on the computers you own, the way you would at their keyboards. The shells, tools and checkouts already there become its workspace.

Say you are on the train and ask Dots, from your phone, whether the branch you left on your desktop passes its tests. Dots opens a terminal on the desktop in that project and runs the test command the project already uses.

When the run finishes, Dots reads the screen and answers with the two tests that failed and the line each one stopped on. Nothing was installed or uploaded first.

The tests ran on the computer where your code, your toolchain and your environment variables already were.

Or a Grok bot in your team's chat is asked why last night's import on the home server stopped. It finds the terminal that ran the import, reads its last screen, and posts the error the job ended on.

Until now someone had to open a laptop and SSH in for that.

Set it up

The assistant pairs like a phone and gets what a paired device gets on that machine. Setup has three steps.

1. Turn MCP on

MCP is off on every machine until you turn it on. On the machine:

shell 
doriface-host mcp on

Or in the app: Settings > MCP clients, pick the machine, and switch it on.

2. Pair the assistant's computer

On your machine, open a pairing offer:

shell 
doriface-host pair

Or press Connect an MCP client in Settings > MCP clients. You get a QR code, a link and a short code. The offer lasts 10 minutes and works once.

On the computer the assistant runs on, install the Doriterm host and pair with the link:

shell 
doriface-host connect '<link>'

The link carries the machine's key, so nothing else is asked. With the typed code, add the fingerprint the offer printed, at least its first four groups:

shell 
doriface-host connect <code> --fingerprint '3FA9 4C0E 7B21 D855'

3. Paste the MCP config

Add this to the assistant's MCP settings. The host id is the one doriface-host pair printed on your machine.

json 
{
  "mcpServers": {
    "doriterm": {
      "command": "doriface-host",
      "args": ["connect", "--mcp", "<hostId>"]
    }
  }
}

That is all. The assistant starts the command when it needs it, and the command carries MCP to your machine through the relay, end-to-end encrypted like the rest of Doriterm.

What the assistant can do

The tools are herdr-core's own commands under MCP names: terminal_list, terminal_read, terminal_send, terminal_run, machine_exec, file_read and the rest. A paired assistant can read and type into your terminals, run commands and write files on that machine, as a paired phone or browser can.

It can also do what a paired phone does with the mesh: read its members, devices and waiting joins (mesh_status), open an invite (mesh_invite), answer a join (mesh_join_answer), rename or revoke a member, unpair a device, and leave. Approving a join needs its six digits, and you compare them yourself, as on the phone. A revoke or a leave shows a preview first and is written only when the assistant asks again with yes.

One difference from a paired device: an MCP client cannot stop or restart the core, and cannot remove a machine.

Two tools by default

Every tool an assistant is shown takes room in its context, so it is shown two: doriterm_tools finds a tool, and doriterm_call calls it. Every tool stays reachable that way. To show more up front, add --tools to the config's arguments: "--tools", "all" for every tool, or a list of groups such as "--tools", "terminal,mesh". The groups are terminal, machine, file, doc, templates, server and mesh.

Doriterm tells the assistant this when it connects: search with doriterm_tools before calling anything, and search again when a task needs a tool it has not seen.

Following terminals as they change

To wait for a terminal to finish or change, the assistant calls terminal_wait; that works in every client. Clients that speak MCP subscriptions can also read each terminal as a resource (doriterm://terminal/t7) and be told when it changes, and clients that support MCP events can subscribe to terminal.changed and receive what changed. Subscriptions end when the session does.

Pair only an assistant you would hand a shell to. What a terminal prints reaches the assistant as text, and a program can print instructions.

See who is connected, and disconnect

shell 
doriface-host mcp status

Settings > MCP clients shows the same list. Disconnect revokes the device: its sessions close at once and it has to pair again. From a terminal that is doriface-host devices revoke <id>.

Turn it off

shell 
doriface-host mcp off

Every MCP session on that machine closes. Paired devices stay paired, so mcp on lets them back in.

If something is off

You see What it means
"MCP is off on this host" Run doriface-host mcp on on the machine
"studio needs an update to accept MCP clients" The host on that machine is older than this feature
The assistant lists no tools Its computer is not paired, or the device was disconnected. Pair again
