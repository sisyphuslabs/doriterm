MCP 클라이언트에서 Doriterm 쓰기

MCP(Model Context Protocol)를 쓰는 어시스턴트가 Doriterm으로 내 머신의 터미널을 다룹니다. 터미널 목록을 보고, 화면을 읽고, 에이전트에게 메시지를 보내고, 명령을 실행합니다. Grok 봇, Pickle, Dots 같은 외부 어시스턴트가 이렇게 붙습니다.

어시스턴트는 휴대폰처럼 페어링하고, 그 머신에서 페어링된 기기와 같은 권한을 받습니다. 설정은 세 단계입니다.

1. MCP 켜기

MCP는 켜기 전까지 모든 머신에서 꺼져 있습니다. 머신에서 실행합니다.

shell 
doriface-host mcp on

앱에서는 설정 > MCP 클라이언트에서 머신을 고르고 스위치를 켭니다.

2. 어시스턴트의 컴퓨터를 페어링하기

내 머신에서 페어링 초대를 엽니다.

shell 
doriface-host pair

앱에서는 설정 > MCP 클라이언트의 MCP 클라이언트 연결을 누릅니다. QR 코드, 링크, 짧은 코드가 나옵니다. 초대는 10분 뒤 만료되고 한 번 쓰면 끝납니다.

어시스턴트가 도는 컴퓨터에 Doriterm 호스트를 설치하고, 링크로 페어링합니다.

shell 
doriface-host connect '<링크>'

링크에 머신의 키가 들어 있어서 더 묻는 것이 없습니다. 짧은 코드로 페어링할 때는 초대에 같이 출력된 지문을 앞의 네 묶음 이상 붙입니다.

shell 
doriface-host connect <코드> --fingerprint '3FA9 4C0E 7B21 D855'

3. MCP 설정 붙여넣기

어시스턴트의 MCP 설정에 아래 내용을 넣습니다. 호스트 ID는 내 머신에서 doriface-host pair가 출력한 값입니다.

json 
{
  "mcpServers": {
    "doriterm": {
      "command": "doriface-host",
      "args": ["connect", "--mcp", "<hostId>"]
    }
  }
}

이게 전부입니다. 어시스턴트가 필요할 때 이 명령을 실행하고, 명령은 릴레이를 거쳐 MCP를 내 머신으로 보냅니다. Doriterm의 다른 연결처럼 종단 간 암호화됩니다.

어시스턴트가 하는 일

herdr-core의 명령이 MCP 이름으로 도구가 됩니다. terminal_list, terminal_read, terminal_send, terminal_run, machine_exec, file_read 등이 있습니다. 페어링된 어시스턴트는 그 머신에서 터미널을 읽고 입력하고, 명령을 실행하고, 파일을 씁니다. 페어링된 휴대폰이나 브라우저와 같습니다.

페어링된 휴대폰이 메쉬에서 하는 일도 합니다. 멤버와 기기, 대기 중인 조인을 읽고(mesh_status), 초대를 열고(mesh_invite), 조인에 답하고(mesh_join_answer), 멤버 이름을 바꾸거나 멤버를 내보내고, 기기 페어링을 끊고, 메쉬에서 나갑니다. 조인을 승인하려면 여섯 자리 숫자가 필요하고, 휴대폰에서처럼 숫자는 직접 비교합니다. 내보내기와 나가기는 먼저 미리보기를 보여 주고, 어시스턴트가 yes로 다시 요청해야 반영됩니다.

페어링된 기기와 다른 것은 하나입니다. MCP 클라이언트는 코어를 멈추거나 재시작하지 못하고, 머신을 제거하지 못합니다.

기본은 도구 두 개

어시스턴트에게 보이는 도구는 모두 컨텍스트를 차지하므로 기본으로 두 개만 보입니다. doriterm_tools는 도구를 찾고, doriterm_call은 찾은 도구를 호출합니다. 모든 도구를 이 방법으로 쓸 수 있습니다. 처음부터 더 보이게 하려면 설정의 인자에 --tools를 더하세요. "--tools", "all"은 전부, "--tools", "terminal,mesh"는 그 그룹만 더합니다. 그룹은 terminal, machine, file, doc, templates, server, mesh입니다.

Doriterm은 연결될 때 어시스턴트에게 이렇게 알려 줍니다. 무엇이든 호출하기 전에 doriterm_tools로 찾고, 처음 보는 도구가 필요하면 다시 찾으라고요.

터미널 변화 따라가기

터미널이 끝나거나 바뀌기를 기다릴 때는 terminal_wait를 호출합니다. 모든 클라이언트에서 됩니다. MCP 구독을 지원하는 클라이언트는 터미널을 리소스(doriterm://terminal/t7)로 읽고 바뀔 때 알림을 받을 수 있고, MCP 이벤트를 지원하는 클라이언트는 terminal.changed를 구독해 무엇이 바뀌었는지 받습니다. 구독은 세션이 끝나면 함께 끝납니다.

셸을 맡겨도 되는 어시스턴트만 페어링하세요. 터미널에 찍힌 글자는 그대로 어시스턴트에게 가고, 프로그램은 지시문을 찍어 보내기도 합니다.

연결된 클라이언트 보기와 끊기

shell 
doriface-host mcp status

설정 > MCP 클라이언트에도 같은 목록이 나옵니다. 연결 끊기는 그 기기를 취소합니다. 세션이 바로 닫히고, 다시 쓰려면 새로 페어링해야 합니다. 터미널에서는 doriface-host devices revoke <id>입니다.

끄기

shell 
doriface-host mcp off

그 머신의 MCP 세션이 전부 닫힙니다. 페어링은 그대로라서 mcp on을 하면 다시 붙습니다.

뭔가 안 될 때

보이는 문구 뜻
"MCP is off on this host" 머신에서 doriface-host mcp on을 실행합니다
"studio needs an update to accept MCP clients" 그 머신의 호스트가 이 기능보다 오래된 버전입니다
어시스턴트에 도구가 하나도 안 보임 그 컴퓨터가 페어링되지 않았거나 기기가 끊겼습니다. 다시 페어링합니다
